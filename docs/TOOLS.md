# Agent tool results

What each tool in `shared/tools.json` returns. The Python executor (`backend/app/engine/tools.py`) and the browser's TS executor (`src/ai/tools.ts`) return exactly these shapes and the same error strings, so teacher traces, eval and the live app agree. `make tool-parity` runs `tests/fixtures/tool_script.json` through both and requires identical JSON (no tolerances are needed today).

Rounding: %, mm, mL and degrees to 1 decimal, halves up (`Math.round(x * 10) / 10`). Plane normals to 4 decimals. Counts are integers. Any failure is `{"error": "..."}`; a tool never throws. Arguments are schema-validated before a tool runs (the backend validates model calls; Python validates again).

Structure ids are the case's label keys (`liver`, `tumor`, `ivc`, `portal_vein`, `aorta`, `kidney_left`, `kidney_right`, `hepatic_vessels`). `measure distance` also accepts `plane` (the current cut). An unknown id is `unknown structure "x"; valid ids: <sorted ids>`.

Cut metrics (`flr`, `margin`, `vessels_crossed`, `optimize_plane`, `resect`, `write_plan.metrics`) belong to the liver case; on another case they are `the <kind> case is not a liver resection case; cut metrics need the liver case`. Stent tools on a non-aorta case: `stent grafts are for the aorta case; "<id>" is a <kind> case`. No cut yet: `no cut placed yet; use set_plane or optimize_plane first`.

The stent JSON (`<stent>` below) is `{device_id, s0_mm, length_mm, diameter_mm, oversize_pct, rules: [{id, pass, value, limit, unit}], rules_source, seals}`. Rules in check order: `renal` (value = s0 minus lowest renal ostium, mm, null without ostia, limit 0, fails if negative or an ostium is covered), `neck_length` (mm, limit 10), `oversize` (%, limit [10, 20]), `angulation` (unit `deg`, limit 60, must be below). `seals` = all pass. `rules_source` is `default` (the simplified EVAR rules) or `ifu:<card id>` when `device_id` resolves to a rule card in `data/device_rules/` (name match ignores case, punctuation and filler words like "AAA" or "endoprosthesis": `gore_excluder`, `Gore Excluder` and `excluder` all resolve to `gore-excluder`). A card replaces the limits it states: `neck_length` limit, `oversize` range (a fresh device is sized at its midpoint), `angulation` limit (inclusive, as IFUs write "<= 60"), and adds `neck_diameter` (mean lumen diameter over the first 15 mm, mm, limit [min, max]) after `neck_length`. Limits a card does not state keep the default.

| Tool | Result | Notes |
|---|---|---|
| `get_state` | `{case_id, case_kind, mode, plane: {normal: [x,y,z], d} \| null, stent: <stent> \| null, thresholds: {margin_min_mm, flr_min_pct}, visible: [ids]}` | `plane` is null until a cut is placed (by a tool, voice or hand). |
| `measure` | `{what, value, unit, method}` | `flr` % (kept organ voxels / organ voxels x 100, organ = liver + tumour). `margin` mm (min tumour EDT over kept organ voxels within one voxel diagonal of the plane; 0 if tumour kept). `vessels_crossed` unit `""` (6-connected vessel components in the cut band inside the organ box, >= 120 mm^3). `tumor_volume` mL (full-resolution tumour voxels x voxel volume). `neck_length`, `neck_diameter` mm (aorta case; current stent, else the default seat). `distance` mm between two structures: the app's on-screen gap (exact EDT from the smaller structure on the full-resolution labels, min over the other's voxels, minus the mean voxel size; error beyond 120 mm); it also shows both structures. With `plane`: min abs signed distance over the structure's planning-grid voxels, 0 if the plane cuts it. |
| `set_plane` | `{plane: {normal, d}, flr_pct, margin_mm, vessels_crossed, tumor_incomplete}`; non-liver case: `{plane, note}` | `normal` + `d` set the plane (both required together; the normal is normalized, `d` is kept as mm along it). `rotate_deg {axis, deg}` turns the normal about a world axis, pivoting on the point of the cut nearest the tumour centroid (organ centroid without one). `offset_mm` then adds to `d` (positive = toward the resected side). They compose in that order. Relative moves with no cut start from the default plane (normal +x through the organ centroid). |
| `optimize_plane` | `{plane, before: {flr_pct, margin_mm, vessels_crossed}, after: {same}, feasible, reason_codes: [...], angle_deg, offset_mm}` | The app's optimize: local search (+-20 deg, +-15 mm) when the cut goes through the organ (2 % < FLR < 99.5 %), then the wide search around the tumour if that is infeasible and the wide answer scores > 0.5 better. No usable cut: wide search. The plane moves to the answer. `margin_min_mm` / `flr_min_pct` update the session thresholds. `avoid` (structure ids) switches to the "vessels" priority. `max_rotate_deg` / `max_offset_mm` bound the local search (cone half-angle; offsets -floor(max)..floor(max) mm) and disable the wide fallback, so the answer stays within them; with no usable cut the wide search still runs. `reason_codes`: what the starting plane violated (`tumor_incomplete`, `margin_below_min`, `flr_below_min`, `vessels_crossed`) or `no_cut`, then `local_search` or `wide_search`, then `avoid_crossed` if the answer still divides an avoided structure. Error on a case without a tumour. |
| `place_stent` | `<stent>` | Aorta case only. Without `s0_mm`: nearest sealing seat to 2 mm below the lowest renal ostium (1 mm scan). With `s0_mm`: that seat, clamped to the centerline. `length_mm` default 80, clamped to [20, centerline length]. Device sized 15 % over the 15 mm neck mean at its seat (a card's oversize midpoint). Checked against the device's rule card when it has one. |
| `optimize_stent` | found: `{found: true, moved_mm, ...<stent>}`; not found: `{found: false, failing_rule}` | Keeps the device's diameter and slides it +-40 mm (1 mm steps, nearest first). `failing_rule` is the rule id that failed most often across the search. With no stent placed, starts from the default seat (sized there); a found seat is placed. |
