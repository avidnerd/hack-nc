# Decisions

One line per decision: date, decision, reason. Code carries a matching `// DECISION:` (or `# DECISION:`) comment where relevant.

- 2026-10-19: `CLAUDE.md` stays gitignored, as in v1. Reason: v1 kept agent notes out of the repo on purpose (`.gitignore`). There was no HackNC `CLAUDE.md` in this checkout, so `docs/CLAUDE_hacknc.md` was not created.
- 2026-10-19: Optimizer timing test takes the best of two runs and honours `PERF_SLACK` (CI sets 2). Reason: single cold timings ranged 405 to 650 ms on one machine under load; the worker pays JIT warm-up at case load, so the warm number is what a user sees.
- 2026-10-19: Frame time is measured by `scripts/frametime.mjs` into `metrics/frametime.json`, hands off. Reason: "measure, never estimate"; camera input cannot run under automation.
- 2026-10-19: Backend lives in `backend/` (FastAPI, Python 3.11, `uv`-managed). Token Factory is called with the `openai` Python SDK against its OpenAI-compatible base URL. Reason: one client for Token Factory and for our own vLLM endpoint, which is also OpenAI-compatible.
- 2026-10-19: LICENSE copyright holder is "the Scrub+ authors". Reason: no legal name given; change if the team wants names.
- 2026-10-19: "Nano few-shot" baseline = our `scrub-nano` endpoint serving Nano 9B v2 without the LoRA. Reason: Token Factory does not list Nano 9B v2 (PLATFORM_NOTES section 2); the brief's fallback applies. Nemotron 3.5 Lightning on Token Factory may be added as an extra row only if verified to support tools.
- 2026-10-19: LoRA targets attention and MLP projections only (q/k/v/o_proj, up/down_proj), not the Mamba in_proj/out_proj. Reason: vLLM documents LoRA for NemotronH but not for the Mamba layers; this keeps the adapter servable without merging.
- 2026-10-19: VISTA-3D full-scan job requests hepatic tumor (26) and hepatic vessel (25) by class id in addition to "everything". Reason: both are excluded from the default 117-class set.
- 2026-10-20: The Python engine (`backend/app/engine/`) is a line-for-line port of the TS planning engine, held to it by `tests/fixtures/parity.json` (`make parity`). Reason: teacher traces, the verifier and eval must run tools without a browser and get the numbers the HUD shows.
- 2026-10-20: `optimize_plane` runs the app's full optimize flow (local, then wide fallback, from `main.ts optimizePlan`), and its `margin_min_mm` / `flr_min_pct` change the session thresholds for good. Reason: matches a spoken "optimize for a 12 mm margin".
- 2026-10-20: `optimize_plane.avoid` maps onto the existing "vessels" priority; `max_rotate_deg` / `max_offset_mm` bound the local search and turn off the wide fallback. Reason: the engine has no per-structure penalty, and adding one would change the TS engine.
- 2026-10-20: Stent `device_id` is free-form and every device uses the default simplified EVAR rules until M4 rule cards exist. Reason: there is no device catalog yet.
- 2026-10-20: `optimize_stent` with no stent placed starts from the default seat (2 mm below the lowest renal ostium), sized there. Reason: the app only optimizes a placed stent; the agent may ask first.
- 2026-10-20: `measure tumor_volume` counts full-resolution label voxels (matches `meta.truth.tumorVolumeMl`); `distance` is voxel-centre distance on the planning grid. Reason: one documented formula each, cheap to mirror in TS.
- 2026-10-20: Browser tools (`src/ai/tools.ts`) run through the voice code paths, and their spoken lines are held back for the length of an agent turn (`quietSay`). Reason: the screen must move exactly as for voice, but only the agent's grounded reply should be said.
- 2026-10-20: Tool calls on a `done` reply are still executed. Reason: the backend cannot run the engine, so any call it sends is for the browser.
- 2026-10-20: If an agent turn fails after a tool ran, the regex grammar does not replay the command; the reply is a template built from the tool results. Reason: replaying would apply a move twice. Before any tool runs, failure falls back to the grammar as specified.
- 2026-10-20: Voice keeps the regex grammar first and sends only misses to the agent; the typed palette sends to the agent first, then the grammar. Reason: the hot v1 demo commands stay instant by voice, and the palette is where judges see the agent work.
- 2026-10-20: `optimize_plane.avoid` naming any vessel switches the search to its vessels-first weights; `max_rotate_deg` and `max_offset_mm` are checked on the answer (one beyond them is reported with `applied: false`, not applied). Reason: the engine's search cone is fixed and its maths is out of scope for M1.
- 2026-10-20: `place_stent` with `s0_mm` evaluates the device exactly there, sized for that seat (15 % over its neck); without `s0_mm` it is the v1 placement. `device_id` is recorded but every device uses the default simplified EVAR rules until M4.
- 2026-10-20: `resect` opens a "Planned resection" card with the engine's numbers; the block animation is M5. Reason: v1 has no resect command.
- 2026-10-20: `set_plane` rotation: the normal turns right-handed about the world axis, the plane keeps passing through the tumour centroid (else the organ centroid) projected onto the current plane, then `offset_mm` slides along the new normal. The Python twin must use the same pivot.
- 2026-10-20: Tools read the plane's animation destination, and `optimize_plane` lands a running animation first. Reason: chained calls in one turn otherwise built on a mid-animation frame (caught by the e2e tools test).
- 2026-10-20: Tool results carry a few fields beyond the M1 brief, for the model: `get_state.case_kind` and `plane_on`, `optimize_plane.applied`, `measure.tumor_incomplete` (margin with tumour left behind), `place_stent.neck_mm`, `angulation_deg` and `rules_source`, `optimize_stent.moved_mm`, `set_plane.note` (non-liver case). Stent rule ids: renal_clearance, neck_length, oversize_min, oversize_max, neck_angulation; angle unit "°".
- 2026-10-20: The `/` key opens the command palette; `?` alone toggles the help overlay. Reason: CLAUDE.md section 8 assigns `/` to the palette.
- 2026-10-20: After a failed agent request (network, timeout, 502/503) the client skips the agent for 30 s. Reason: voice would otherwise wait up to the 7 s timeout on every missed phrase while the backend is down.
- 2026-10-20: Every e2e test uses `e2e/fixtures.ts`, which fails on any `console.error` or page error and answers `/api/health` (Token Factory off) and `/api/grounding` (no totals). Reason: CLAUDE.md section 8, and Chromium logs any failed request as a console error, so tests must not depend on a running backend. `E2E_PORT` lets a worktree run its own dev server.
- 2026-10-20: The two tool executors (Python `backend/app/engine/tools.py`, TS `src/ai/tools.ts`) now return identical JSON, checked call by call by `make tool-parity` (tests/fixtures/tool_script.json). docs/TOOLS.md is the contract; this supersedes the earlier lines on TS-only fields, `applied` and rule ids. Reason: the distilled model learns from Python results and runs against the TS ones.
- 2026-10-20: `optimize_plane.max_rotate_deg` / `max_offset_mm` bound the local search (cone half-angle; offsets floor(max) mm) and turn off the wide fallback, on both sides; no `applied` field. Reason: the answer then always respects the limits, instead of the TS check-after that often left the cut unchanged. With no usable cut the wide search still runs (nothing to be local to). The default search is unchanged.
- 2026-10-20: `optimize_plane.avoid` with any id switches to the vessels-first weights (Python rule); `feasible` is the engine's verdict and an avoided structure still cut adds `avoid_crossed`. Reason codes are the Python set: start violations or `no_cut`, then `local_search` / `wide_search`, then `avoid_crossed`.
- 2026-10-20: Stent rules are `renal`, `neck_length`, `oversize` (limit [10, 20]), `angulation` (unit "deg"); `renal.value` is null without ostia. Stent JSON gains `rules_source: "default"` on both sides (M4 sets it when a Tavily rule card drives the verdict). `neck_mm` / `angulation_deg` are dropped: they are the rule values.
- 2026-10-20: Kept from TS and added to Python: `get_state.case_kind` (and `write_plan.case_kind`, renamed from `kind`), `set_plane.note` on a non-liver case, and the liver-only rule for cut metrics (`flr`, `margin`, `vessels_crossed`, `optimize_plane`, `resect`, `write_plan.metrics`). Dropped from TS: `plane_on` (plane is null until a cut), `measure.tumor_incomplete`, distance's `a`/`b` echo, `optimize_stent.search_mm`, and write_plan's `case_name`, `organ_ml`, `tumor_ml`, `files`.
- 2026-10-20: `measure distance` between structures is the app's on-screen measurement (smartMeasure.ts: exact EDT on the full-resolution labels from the smaller structure, minus the mean voxel size, error beyond 120 mm), ported to Python; it also shows both structures, as the app's view does. `neck_length` / `neck_diameter` work without a stent (default seat) and `optimize_stent` without one starts from the default seat, in TS too. Supersedes the planning-grid voxel-centre distance.
- 2026-10-20: `set_plane` with `normal` + `d` keeps `d` as given and normalizes the normal (Python rule; TS used to divide d by |normal|); absolute, rotate and offset compose in that order on both sides; relative moves with no cut start from the default plane. `show highlight` also makes the structures visible on both sides (what the app's "show" does). `place_stent` clamps `s0_mm` and `length_mm` to the centerline on both sides instead of erroring.
- 2026-10-20: `failing_rule` maps fail reasons by prefix on both sides. Reason: the old Python table missed "Neck angled 62 degrees", whose text has no comma.
- 2026-10-20: The browser probes `/api/health` and `/api/grounding` only in dev or when `VITE_AGENT_URL` is set. Reason: the static Vercel build has no backend, and Chromium logs the 404s as console errors.
- 2026-10-22: Super is `nvidia/nemotron-3-super-120b-a12b` (from GET /v1/models). The "Nano few-shot" baseline is `nvidia/NVIDIA-Nemotron-3-Nano-30B-A3B` on Token Factory (tools supported), because Nano 9B v2 is not served there. Reason: CLAUDE.md section 5 prefers a Token Factory baseline when one exists; the un-tuned 9B on our endpoint can be added as a fourth row if time allows.
- 2026-10-22: Agent replies are stripped of leading/trailing whitespace. Reason: Super's final text starts with a newline.
- 2026-10-22: Super's paraphrases are cached in `distill/data/paraphrases.json` (committed) and reused by every later `gen_commands.py` run, so `commands.jsonl` rebuilds byte for byte. Paraphrase calls get 4000 max tokens (at 400 Super's reasoning used them all and returned nothing). The distill test writes its command set to a temp file. Reason: pytest was overwriting the paraphrased 6,000-command set.
- 2026-10-22: Agent calls get 2048 max tokens instead of 512. Reason: in the teacher pilot, Super's reasoning used the 512 after long tool results and the final reply was empty (2 of 40 traces).
- 2026-10-22: VISTA-3D full-scan Job uses the public `pytorch/pytorch:2.4.0-cuda12.4-cudnn9-runtime` image, pip-installs MONAI 1.4 / transformers 4.44 at start (about 20 s), and reads code and inputs from the bucket mounted by id (`--volume storagebucket-...:/data:rw`, no credentials in the job spec). Reason: no registry or Docker build on the critical path; a baked image is a later speed-up.
- 2026-10-22: The job prompts VISTA-3D with the 8 classes the app plans on (liver 1, hepatic tumour 26, hepatic vessel 25, IVC 7, portal/splenic vein 17, aorta 6, kidneys 14/5) instead of the 117-class "everything" pass, then feeds the masks to the unchanged pipeline/run.py. Reason: the app only uses these; hepatic tumour and vessel are not in VISTA's everything set anyway.
- 2026-10-22: Bucket mount limits found: no rename (HF downloader fails), no chmod (shutil.copy fails), no append. The job downloads weights to local disk, copies bytes only, and writes one log file per job.
- 2026-10-22: Gallery is 8 MSD Task03 cases not used by the app (liver_24, 30, 39, 47, 56, 59, 62, 70), and Dice is measured on all 8 against MSD labels. Caveat for RESULTS.md: VISTA-3D's training data includes MSD Task03, so these Dice scores may be optimistic.
- 2026-10-24: Gallery = `public/data/gallery.json` (committed, built by `vista/gallery.py` from `metrics/vista_runs.jsonl`) plus gzipped assets at `VITE_GALLERY_URL` (default `data/gallery/`, gitignored, 66 MB for 8 cases). Opened from a "Gallery" button or `g`; ids start with `msd_`. Reason: keeps 160 MB of binaries out of git; hosting (public bucket or the static host) is the product owner's call.
- 2026-10-24: Eval rows: Super (Token Factory), Nano 30B A3B (Token Factory, `nano-tf`), Nano 9B v2 base and + LoRA (our endpoint, served names `base` / `scrub`). Nano 9B gets `/no_think` appended to the system prompt exactly as in training. Prices from GET /v1/models (metrics/tf_models.json). Supersedes the 2026-10-19 baseline line.
- 2026-10-24: LoRA runs 1-3 failed: missing pad token (fixed: pad = eos), then divergence with and without `down_proj` (eval loss 0.71 base -> 1.79 after 2 epochs, grad norm 1e8 to 1e13). `distill/job/diag.py` tests the training path before another full run.
- 2026-10-25: LoRA config for run 4 (`lora-1025-1409`): attention + MLP `up_proj` in layers 8-55 (PEFT `layers_to_transform`). Reason: `distill/job/diag.py` showed `up_proj` LoRA in squared-ReLU MLP layers 1/3/5 gets ~2e7 gradients, so global clipping starved every other adapter; on one batch the old set went 0.79 -> 0.79 in 30 steps, this one 0.79 -> 0.07 (no clipping 0.03, attention only 0.18, + Mamba projections 0.79). Run 4 eval loss: 0.710 base -> 0.237 at step 100.
- 2026-10-25: Serve merged weights (`distill/job/merge.py`), not `--enable-lora`. vLLM 0.11's LoRA manager asserts at startup on NemotronH even with no adapter. The base model and the merged model run as two endpoints (`scrub-nano-base`, `scrub-nano-scrub`), one at a time within the tenant's limit of 2 instances.
- 2026-10-25: macOS has no `timeout`; the earlier `timeout 100 nebius ai job cancel` never ran, which is why run 3 used its full 2 h. Cancels now run directly.
- 2026-10-25: M4 rule cards live in `data/device_rules/<id>.json` (committed) and are bundled into the client with `import.meta.glob`, so the static demo shows them without Tavily or a backend. The live lookup is `GET /api/rules?device=` (`backend/app/rules.py`); the Python engine reads committed cards only, so it stays deterministic.
- 2026-10-25: A rule card field is kept only if its quote appears in the source text Tavily returned for its URL (whitespace, dashes and <=/≤ normalised), every number of its value appears in the quote, and the value is in a plausible range. Otherwise it is "not found" and the default rule applies, labelled as such.
- 2026-10-25: Tavily searches the manufacturer's domain first and FDA only for fields still missing; product pages of sibling variants (`/products/excluder-conformable` for "Excluder") are dropped. Reason: the first two Gore lookups returned the Excluder Conformable's limits (16-32 mm, 10 mm, 90 deg), from a shared product page and then from its PMA P200030, all verbatim, so verbatim checks alone cannot catch a wrong-device quote.
- 2026-10-25: A card replaces the neck length minimum, oversize range (sizing at its midpoint, 15 % for the default 10-20), angulation maximum (inclusive) and adds a neck diameter range rule checked after neck length. Its fail reason uses one decimal ("Neck diameter 18.6 millimeters, below the device minimum of 19") because whole millimetres read "19" against a 19 mm minimum.
- 2026-10-25: Gore Excluder card (from goremedical.com/products/excluder/specifications): neck 19-32 mm, length >= 15 mm, angulation <= 60 deg; oversizing not stated there, so the default 10-20 % stays. On the aorta case (neck mean 18.6 mm) the Excluder does not seal; the generic default rules still seal. This is a real result of the sourced rules, not a bug.
- 2026-10-25: distill/ sets `SCRUB_DEVICE_RULES=0` so teacher traces, verification and every eval row use the default rules the training data was verified against (14 of 6,000 commands name Gore or Endurant).
